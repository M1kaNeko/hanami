# 花间 v0.1.0 · 交付与验证

## 交付物

- `Hanami-0.1.0-windows-arm64.zip`：Windows ARM64 便携版。完整解压后运行文件夹里的 `Hanami.exe`。适用于当前这台 Apple Silicon Mac 的 Windows 11 ARM 虚拟机。
- `Hanami-0.1.0-source.zip`：源码、锁文件、测试、运行与打包脚本。解压后进入 `app/`，执行 `npm ci` 和 `npm run dev`。
- `hanami-empty.png`、`hanami-library.png`、`hanami-details.png`、`hanami-narrow.png`：实际 Electron 窗口截图。截图中的三个作品是测试用的虚构示例，交付应用初始为空库。

## 已实际验证

- 完整自动测试：7 个文件、37 项全部通过。
- TypeScript 类型检查及生产构建通过。
- Mac 上实际启动 Electron 生产页面，验证隔离 IPC 可读写真实测试目录。
- 通过界面新增三条记录，编辑状态、评分、感想，关闭应用并重开，确认三条记录及感想仍在。
- 对 Windows 交付目录中提取的应用资源，用 Mac 的 Electron 运行时重复上述桌面检查，确认资源、模块路径及本地依赖完整。
- 页面没有 JavaScript 异常，700px 宽窗口没有横向溢出。
- Windows 运行时压缩包 SHA-256 与对应 SHASUMS256 一致；交付 exe 的 PE 文件头为 Aarch64。
- PNG / JPEG / WebP 均经过实际解码检查；多 MiB PNG 的导出导入往返通过。
- 缺失旧封面、损坏 JSON、非法备份、写入失败、重复路径、删除原游戏文件保护，均有测试覆盖。

## Windows 待测

发现的 Windows 11 ARM64 虚拟机已恢复运行，但没有已登录用户，尚未验证 Windows 图形界面与真实 galgame 启动。Windows 游戏兼容性不能由 Mac 端测试推断。

登录后建议依次检查：

1. 解压便携包，双击 `Hanami.exe`，确认出现空书架。
2. 添加位于含中文、空格目录里的真实游戏，在 Windows 内选择 .exe。
3. 启动游戏、打开目录；实际进程创建成功不代表所有旧游戏均能正常运行。
4. 编辑状态、评分、感想，重开应用确认保存。
5. 导出备份，确认文件存在；修改书架后恢复，确认记录及封面恢复。
6. 移出一条收藏，确认原游戏目录与程序仍在。

该包未签名。没有交付或声称已生成 NSIS 安装器；本次交付为完整便携 ZIP。

## 实施中的取舍

- 全新项目在本地 `feat/galgame-manager` 分支开发，没有既有主分支需要合并，也没有推送远端。
- 用当前会话连续实现，最后进行一次独立代码审阅；审阅发现的五项问题均先复现再修复，并通过全套测试。
- 恢复时重新生成内部封面文件名，避免在切换书架前覆盖旧封面；图片内容与记录保持不变。
- 该 Mac 上原生工具的文件打包过程曾卡在文件读取，配置加载改用 runner，桌面模块由 Node 读取后逐文件转译。开发命令先构建再预览，修改代码后重启命令。
- 标准 NSIS 流程在运行时下载后停滞，改用 Node 解压运行时并复制完整生产资源生成 ARM64 便携包。完整包包含纯 JS / WASM 图片解码依赖。
- 先保留设计和测试范围内的手动添加、启动、记录与备份；联网抓资料、存档管理、计时、云同步暂未实现。

完整操作说明在源码中的 `app/README.md`。
