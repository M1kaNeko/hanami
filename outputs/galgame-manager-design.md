# Galgame 管理器：第一版设计

日期：2026-10-21

## 目标与约定

为个人本地 galgame 收藏提供 Windows 桌面管理器：找到游戏、启动游戏、记录游玩状态和感想。源码在 Mac 上开发，Windows 虚拟机用于真实启动与安装验证。

已确认：封面书架、搜索筛选、手动添加、一键启动、状态记录、评分感想、本地保存及备份。默认采用中文、浅色界面；自动获取资料、云同步、存档管理和游玩计时不在第一版内。

## 实现方案

建议使用 Electron + React + TypeScript：界面可以在 Mac 上预览，由桌面主进程处理文件、数据和程序启动。

另两种选择：Tauri 更偏向轻量分发，但需额外维护 Rust 与系统工具链；浏览器应用便于分享，但不能直接满足 Windows 本地程序启动。第一版选择 Electron，以贯通本地使用流程为优先。

Windows 安装包以 Windows 构建为验收依据。优先在虚拟机中构建和验证；不预先保证 Mac 能直接产出可用的 Windows 安装包。运行库版本与打包配置在实施时核实。

## 页面与交互

主窗口左侧显示全部、想玩、在玩、已通关、搁置以及对应数量；上方提供搜索、标签筛选和添加按钮；主体展示封面卡片。搜索匹配名称和标签，搜索与状态、标签筛选可以组合。

空库显示添加引导。无封面时显示名称占位卡，不依赖外部图片。点击卡片打开详情，可编辑名称、封面、标签、目录、启动程序、状态、评分和感想，也可启动或打开目录。缺失文件时保留记录，并提供重新选择路径的入口。

添加流程：选择游戏目录 → 选择其中的 .exe → 确认名称 → 可选添加封面和标签 → 保存。名称默认取目录名，可修改。相同启动路径不重复添加。编辑与添加使用同一表单规则。

状态为想玩、在玩、已通关、搁置，新添加默认为想玩。评分可不填，填写时为 1–10 的整数。启动游戏不会自动更改状态。删除操作需要确认，只移除管理记录及应用内封面副本，不删除游戏文件。

## 数据与文件

每条记录包含稳定 ID、名称、游戏目录、启动路径、封面引用、标签、状态、可空评分、感想、创建与更新时间、最近启动时间。列表按最近更新排序。

数据保存在应用用户数据目录内，使用带 schemaVersion 的 JSON 文档。封面导入为应用管理的副本，以相对引用关联，避免依赖原图位置。写入采用临时文件与替换，并保留上一次有效数据。读取异常时明确报错，保留原文件，不把损坏数据当空库覆盖。

导出为单个备份文件，包含清单和封面，不包含游戏程序及存档。导入先验证结构、版本和图片路径，再确认替换当前库；替换前自动备份。Windows 绝对路径保留原值，迁移后通过编辑修复。

## 系统行为与隔离

界面只通过有限 IPC 接口调用主进程：读写游戏记录、选择文件、导入封面、启动、打开目录、导入导出。渲染层不直接执行命令或访问任意文件。

启动前检查目标存在且为 .exe，以参数数组调用进程接口，不拼接 shell 命令；工作目录设为启动程序所在目录。路径包含中文、空格时仍应可用。记录启动成功指操作系统成功创建进程，不保证游戏随后正常运行。失败展示可理解的错误信息。

Mac 上可测试书架、编辑、数据和备份；Windows 程序启动入口显示平台提示。Mac 路径不能作为 Windows 虚拟机中的游戏路径，实际启动路径在 Windows 运行时选择。第一版不提供兼容层集成或启动参数编辑。

## 模块与验证

界面负责展示和表单；领域模块负责校验、搜索和筛选；存储模块负责迁移与原子保存；系统模块负责文件选择和启动；备份模块负责导入导出。模块通过明确的数据类型与错误结果衔接。

自动检查覆盖筛选组合、输入校验、重复路径、持久化重读、损坏数据保护、备份往返与非法导入，以及启动接口的路径和工作目录传递。界面验证覆盖空库、添加、编辑、筛选和缺失文件提示。

Windows 虚拟机验收：添加位于含中文和空格目录中的真实游戏；成功启动；打开目录；修改状态、评分与感想；重启应用仍保留；备份导出后恢复；删除记录不影响原游戏。未完成此步骤前，只声明已完成 Mac 端开发与检查，不声明 Windows 已验证。
